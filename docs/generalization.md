# 泛化测试：换一套完全不同的语料，还能答对吗

> 复现：
> ```bash
> python tools/build_second_corpus.py      # 抓 3 份政府公开文件、建库
> python tools/eval_generalization.py      # 15 道题
> ```

## 一、为什么做这个

主评测集是"1 份论文 + 5 份产品手册"，全是**说明性、条款式、有明确小节**的文档。
面试官会问：**换一种文档还行吗？**

所以另建一个库，语料换成**政策法规**：
- 《中华人民共和国个人信息保护法》（全国人大，2021）
- 《"十四五"数字经济发展规划》（国务院）
- 《数字中国建设整体布局规划》（中共中央、国务院）

三份都是政府公开发布，中文、条款式、**没有产品手册那种"1.2 退款政策"的短标题**。

| 项 | 主评测集 | 泛化语料 |
|---|---|---|
| 文档 | 6 份（论文 + 产品手册） | 3 份（法规 + 规划） |
| 块数 | 188 | 56 |
| 问题 | 255 条 | 15 条（人工从原文挑事实） |
| **准确率** | **98.4%** | **93.3%（14/15）** |

## 二、结果

```
泛化正确率：14/15 = 93.3%
平均延迟：5.6s
```

## 三、掉的那 5 个点，掉在哪

**唯一失败的题**：`委托处理个人信息时，受托人能否转委托他人？`

原因分析（三层排查）：

1. **检索到了吗**：相关条款在《个保法》原文里，但这段落在一个约 900 字的大块中；
2. **上下文给了吗**：给了，但同一块里同时有"委托、共同处理、合并分立"三件事，
   模型容易只回答前半部分；
3. **答案里没有"转委托"三个字**：模型改成"不得再次委托他人"来说——
   **语义对了，关键词没中**。

这正好暴露了**关键词判定的假阴性**（见 `docs/PROTOCOL.md` 第三节），不是系统答错。

## 四、更值得说的发现：分块策略对法规文本不适配

`个人信息保护法` 结构化后是 **9 节 / 21 块**，但看章节名就知道切错了——
本章正文被切到了"第六章 履行个人信息保护职责的部门"名下。

原因：法规文本的标题格式是 `第X章　总则`（全角空格），而我的标题启发式
（含 `DOT_LEADER`、长度 ≤40、无句末标点）对**没有编号层级的条款文本**判断不准。

**这不是 bug，是适配问题**：同一套分块参数，在产品手册上 71 块切得很好，
在法规上就退化。如果要做法规场景，需要专门处理"第X章/第X条"的层级。

## 五、结论（面试怎么说）

> "我做了泛化测试：把语料从产品手册换成三份政府法规，同一套参数不调，
> 准确率从 98.4% 掉到 93.3%（14/15）。
> 掉的那一题是关键词判定的假阴性——模型答对了但换了说法。
> 但更值得说的是分块：法规的'第X章'标题格式我的启发式识别不了，
> 章节切错了好几处，说明这套分块参数是给产品手册调的，不是通用的。"

**主动报"换语料掉 5 个点 + 根因是分块适配"，比只说"准确率 98%"可信十倍。**

## 六、这次测试的局限

1. 只有 15 道题，1 题就是 6.7 个百分点，**样本太小**；
2. 三份文档都是政府公文，同质化，不算"跨行业"；
3. 语料是 HTML 转 PDF 的，含导航文字，比真实 PDF 干净但结构更差；
4. 没有负样本——拒答能力这一轮没测（主评测集里测过，25/25）。
